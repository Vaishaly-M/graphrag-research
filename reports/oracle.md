# Oracle definitions

Oracle-Route receives only the benchmark's explicit `gold_route` in addition to the normal question/repository inputs. Missing labels fail; they are never inferred from category or question wording. No gold answers, gold Cypher or gold evidence are passed to retrieval or generation.

Fixed Graph, Fixed Hybrid, Oracle-Route and Adaptive share `src/systems/rebuild/shared.py`, `vector.py`, and `engine.py`: the graph retriever, vector retriever, fusion, answer prompt and Gemini settings are identical. Fixed Graph has no vector fallback. Adaptive and Oracle both fall back from an empty selected graph/vector route to hybrid. Oracle additionally obtains any branches Adaptive would request, including its empty-route fallback. Fusion retains distinct evidence text for the same entity and does not preferentially truncate Oracle evidence. This is an evidence-access privilege, disclosed in the configuration; it is not a pure gold-route-only baseline.

The user clarified during Phase 5 that there is **no requirement to prove Oracle performs best**. More evidence does not guarantee a better stochastic answer. Oracle-Route accuracy is measured and may be lower; it is not described as an accuracy upper bound. Independent stochastic Cypher calls can return different rows, so branch coverage alone is insufficient. Oracle additionally unions the exact saved evidence from the compared Adaptive record, without its generated answer or gold answers. The source artifact hash is saved in Oracle's configuration. The runner checks matching system, model, question set, split, run ID and shared retrieval/generation configuration. Smoke runs Adaptive before Oracle for this purpose. Standalone Oracle runs require `--adaptive-results`.

Oracle evidence replay is explicitly marked `oracle_adaptive_evidence_replay`. Its own physical timings are still saved, but excluded from latency means because they omit the prepaid work that produced the compared Adaptive evidence. No zero-cost cache hit is presented as a fair live latency advantage. Accuracy remains included. The evidence-superset unit test includes an extra Adaptive fact that an independent Oracle retrieval does not reproduce.

Oracle-Best-of-3 is post hoc: select one of the saved Fixed Graph, Vector and Fixed Hybrid outputs for each question. The declared objective is strict correctness, then entity F1, then graph/vector/hybrid order. It generates no new answers. Its accuracy bounds those exact three saved candidates. It bounds Adaptive only if Adaptive's exact cached output is one of the candidates; independent generations or different fallback evidence do not establish that condition. `test_posthoc_oracle_ge_each_cached_candidate_including_adaptive_route` tests this conditional bound, not a fabricated empirical superiority result. Separate per-metric maxima would be different oracles and must not be silently mixed.

The smoke command writes `oracle_best_of_three.json` alongside the raw candidate outputs. Its labels are privileged evaluation outputs and must never be inputs to a deployed router. Adaptive currently uses an explicitly provisional always-hybrid policy; a Phase 6 router can be injected through the same interface. No Phase 6 tuning has occurred.
